# rulecheck → auditkit

> **当前方向已调整为 auditkit：判定类 AI 输出的差分审计器。**
> 用独立的确定性 oracle 重算，找出 AI 输出里的缺陷（漏判 / 降级 / 数值错 / 单位错 / 阈值用错 / 引用编造 / 内部矛盾 / 安全越界），
> 定位、给证据、给修复建议，并**用注入式基准证明自己找得全**。
> 完整方案见 [`docs/01-auditkit-plan.md`](docs/01-auditkit-plan.md)。
>
> 底层引擎（`engine/`）不变，仍是本项目的正确性地基：
> **模型只负责听懂人话和解释结果；判定与金额由程序计算，永远不会算错。**

## 为什么需要它（而不是直接用网页版聊天工具）

网页版聊天能给你一段**读起来很像那么回事**的说明和一个数字，但你无法验证那个数字对不对。

判定类业务不能这样。以退改签为例，企业需要的是：

| 需要什么 | 为什么网页版给不了 |
|---|---|
| **金额必须准** | 模型是"写"出一个数字，不是"算"出来的 |
| **结论必须留痕** | 聊天记录不是审计日志；结论要能追溯到具体条款 |
| **必须能接系统** | 要真的查订单、发退款、建工单，不是只输出文字 |
| **口径必须一致** | 同一张票问两次不能得到两个答案 |
| **成本必须可控** | 每次把几十页规则塞进上下文，又贵又慢 |
| **必须有兜底** | 拿不准或金额超限，要能自动转人工 |

判断一个项目值不值得做，有一条简单标准：**如果网页版聊天工具就能替代，那它只是个 demo。**

本项目采用的分工：

```
用户的大白话
   ↓  ① 模型：把话与条款对上（产出结构化事实）
结构化事实
   ↓  ② 程序：算资格、算金额、逐条校验        ← 不含模型，不会算错
判定结果 + 金额 + 命中条款
   ↓  ③ 模型：解释成人话、提示风险
   ↓  ④ 人：低置信度 / 超阈值 → 强制接管
最终答复 + 审计日志
```

- 10 个判定域（8 个医学分级 + 2 个回归夹具）自检：**0 错误**，医学域覆盖率 **100%**
- 判决样本：档案配比**精确命中计划值**（50% / 20% / 15% / 10% / 5%），固定 seed 可逐字节复现
- 缺陷注入基准：**200 份产物 / 198 条已知缺陷 / 80 份干净样本**
  - 干净样本是**误报率的分母**，比例精确 40%；其中 27 份带**合法变体**（给误报率加难度）
  - 漏判（危急值被写成正常）**10 条，吃满其能力上限**
  - 三类"只有 oracle 重算才能发现"的缺陷共 **57 条（28.8%）**
- 确定性检查器：**召回 198/198（100%）、精确率 100%、误报 0 条**

  - 剩下的 2 条是真实的排序错误，留给 A6 的重排解决（继续调参有过拟合风险）
- 审计 agent 端到端（30 份产物、25 条已知缺陷）：

## 快速开始

```bat
:: 1) 准备密钥（只做一次，A1 阶段还用不到）
copy .env.example .env
::    然后用编辑器把你自己申请的 key 填进 DEEPSEEK_API_KEY=

:: 2) 跑冒烟，确认环境通了
.\.venv\Scripts\python.exe main.py

:: 3) 跑全部测试（不需要 API key，不会花钱）
.\.venv\Scripts\python.exe -m pytest -q

:: 4) 规则自检：10 个判定域，报告写到 reports/
.\.venv\Scripts\python.exe -m engine check --all --samples 1000

:: 5) 生成判决样本（被审计对象），输出配比与严重度分布
.\.venv\Scripts\python.exe -m audit synth --count 200

:: 6) 生成带标准答案的评测用例（引擎层）
.\.venv\Scripts\python.exe -m engine gen --all --count 1000

:: 7) 单次判定：肌酐 110，男性 → 轻度；女性 → 明显升高
echo {"sex": "female", "age": 40, "crea": 110} ^
 | .\.venv\Scripts\python.exe -m engine decide --domain domain/med-crea/domain.yaml
```

## 目录

| 路径 | 内容 |
|---|---|
| `engine/` | 纯程序层：受限表达式、域加载、判定、规则自检、评测用例生成（**不含模型**） |
| `agent/` | 模型相关层：流程编排、提示词、越界拦截（M2 起） |
| `tools/` | 给模型用的"按钮"（含参数校验与报错规范） |
| `domain/` | 判定域配置：**规则是数据，不是代码**，换文件即换行业 |
| `eval/` | 评测用例生成与人读抽样；**两层验证的方法论见 `eval/README.md`** |
| `reports/` | 规则自检报告（自动生成，入库作为证据） |
| `docs/` | 产品需求、指标定义、失败模式、能力地图 |
| `learn/` | 12 个小脚本，一个一个教概念 |
