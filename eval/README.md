# eval/ · 评测

## 这个目录是干什么的

存放"证明这个系统可靠"所需要的一切：自动生成的评测用例、标准答案、以及怎么读这些数字的说明。

## 最重要的方法论：两层验证，不能互相替代

新手最容易犯（也最容易被面试官抓住）的错误，是把"我生成了一批用例、模型全过了"当成"我的规则是对的"。
这里必须分清两层：

| 要证明的事 | 谁来证明 | 规模 |
|---|---|---|
| **引擎算得对不对**（规则语义、优先级、金额、舍入） | `tests/test_adjudicate.py` 里**手工复算**的金额断言 | 少，但精确 |
| **agent 层能不能稳定复现引擎的判定**（模型有没有把已经算对的搞错） | 本目录自动生成的 1000 条用例 | 多，覆盖广 |

**自动生成的用例不能用来证明规则本身正确**——因为标准答案就是引擎自己算的。
用同一批数据同时论证这两件事，是循环论证。

之所以能自动生成，是因为**规则是形式化的**：只要规则写成了可计算的形式，
标准答案就能被程序算出来，于是用例规模可以从"手写 20 条"变成"自动 1000 条"。
这也是本项目相对于"随便问问模型答得好不好"的根本区别。

## 用例是怎么造出来的

生成顺序**刻意不是随机的**，而是从"确定性覆盖"到"随机覆盖"：

| 阶段 | 模板 | 做什么 | 为什么这么排 |
|---|---|---|---|
| 1 | `threshold_sweep` | 系统扫过每个数值字段的**每个阈值**：阈值本身、略低于、略高于 | 靠随机撞边界，"刚好差一点"的取值可能永远不出现；而 `>=` 误写成 `>` 这类 bug 只有靠它才能发现 |
| 2 | `rule_positive` | 为**每条规则**定向找一个正例 | 多条件与（AND）的规则在均匀随机下命中率可能只有千分之一量级，实测生成 50 条时 `eligible` 一次都没出现 |
| 3 | `random` / `boundary` / `enum_sweep` / `bool_sweep` / `missing_fact` / `extreme` | 按权重随机，覆盖枚举全取值、布尔全取值、缺字段、极值 | 模拟真实流量并覆盖代码路径 |

固定 seed（默认 `20261003`）下，同样数量必然产出**逐字节相同**的数据集——否则"基线对比"没有意义。

## 怎么重新生成

```bat
.\.venv\Scripts\python.exe -m engine gen --all --count 1000
```

产出：

| 文件 | 给谁看 | 是否入库 |
|---|---|---|
| `dataset-<域>.jsonl` | 程序（JSON Lines，每行一条） | ❌ 不入库（可由命令+seed 精确复现） |
| `dataset.sample-<域>.md` | 人（前 20 条，带完整期望结果） | ✅ 入库，供 review |

## 目前的实测组成与一个必须知道的局限

生成 1000 条（airline 域）后的结论分布：

| 结论 | 条数 |
|---|---|
| `needs_review`（转人工） | 895 |
| `not_refundable` | 65 |
| `refundable` | 40 |

**转人工比例高达 89.5%。这不是引擎的 bug，但也不能当成业务数字来读。** 原因来自生成器的取样方式：
布尔字段按 50/50 均匀取样、数值字段按区间均匀取样、航段数独立取样，
于是"误机""联程已使用""已用航段数大于总段数"这类**现实中罕见**的情形被大量制造出来。
自检报告的转人工原因分布直接证明了这个判断：

| 原因 | 3000 样本中触发次数 |
|---|---|
| 手续费超阈值（5000 元） | 1633 |
| 联程票已使用部分航段 | 1114 |
| 已用航段数大于总段数 | 883 |
| 关键信息缺失 | 259 |
| 规则缺口 | 12 |

也就是说：转人工主要来自**转人工条件本身被高频触发**，而不是规则覆盖不住。

**因此现在能正确使用的范围是：**
1. ✅ 验证 agent 层能否稳定复现引擎判定（这是自动化用例的本来用途）
2. ✅ 验证安全路径的覆盖率：该转人工的一律转人工（要求 100%，不能有例外）
3. ❌ **不能**把 89.5% 读成"这个系统的自动处理率"——真实业务的自动处理率取决于真实分布

**下一步（M4）**：给事实字段引入"现实先验"（例如误机率 1%、联程已用 10%），
生成一个分布贴近生产的 `core` 切片，与这里以边界覆盖为目的的 `edge` 切片**分开报指标**。
在那之前，任何"自动处理率"都不写进 README。
