# 03 · 失败模式分析

> 这份文档是本项目**最能体现判断力**的部分。招聘方明确说过两件事：
> 1. 主动讲失败案例比只讲成功更有说服力；
> 2. 面试会追问"最意外的失败是什么""为稳定性删掉过什么链路"。
>
> 所以这里不写成功，只写"哪里错了 → 为什么错 → 怎么改 → 改完用数据复测"。

---

## 使用规则

每个失败模式一条，编号 `FM-001` 起，四段式固定结构：

| 字段 | 要求 |
|---|---|
| 现象 | 一句话描述用户看到的问题（不要写"模型不好"这种空话） |
| 复现 | 给出可复现的最小输入，别人照着能重现 |
| 归因 | 到底是哪一层的问题：数据 / 规则 / 模型理解 / 提示词 / 代码 / 我的设计 |
| 改法 | 具体改了什么（改代码、改规则、改提示词、改流程） |
| 复测 | 改完后的数据：第几条用例从"错"变"对"，整体指标怎么变 |
| 状态 | 已修复 / 已知不修（写原因）/ 待观察 |

**硬性要求**：至少 8 条；其中至少 1 条必须是"**主动砍掉的功能**"（见文末模板）。

## FM-001 · 待你用网页版聊天工具做实验后填写

**实验步骤**（约 3 分钟）

1. 打开任意网页版聊天工具（不要用本项目的代码）。
2. 构造一条稍微绕的虚构规则，例如：

   > 退票费率按离站时间分档：提前 7 天以上收票面 5%，7 天内至 48 小时前收 15%，
   > 48 小时内收 30%。若票面折扣低于 5 折，上述费率各加 10 个百分点。
   > 联程票已使用其中一段的，按未使用航段比例折算票面后再计费。

   再给一张具体订单，例如：

   > 订单号 A-1001，票面价 15000 元，经济舱，折扣 4 折，联程两段（第一段已使用），
   > 距离第二段起飞还有 5 天，现要求退第二段。

3. **同一个问题连续问三次**（不要改措辞）。
4. 记录下面四件事：

| 观察项 | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---|---|---|
| 算出的金额 | | | |
| 是否说明了依据哪条规则 | | | |
| 算术过程能否被你逐步核验 | | | |
| 是否主动指出"折扣加价"与"联程折算"的先后顺序 | | | |

5. 结论（用你自己的话写）：

**现象**：

**复现**：

**归因**：

**改法**：（现在还不知道怎么改，正常。等 M1 做出判定引擎后回填：说明"改法 = 把这一层交给程序算"）

**复测**：（M4 评测上线后回填：同一批用例在本项目里的金额一致率）
