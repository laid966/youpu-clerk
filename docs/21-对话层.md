# 21 · 对话层：上下文管理与压缩

> 这一层是**新加的**，而且它和审计器**刻意分开**。
>
> 一句话：**审计器无状态（这样才可复现），对话层有状态（这样才好用）。**

---

## 一、为什么必须分成两层

| | 审计器 | 对话层 |
|---|---|---|
| 判什么 | 这份报告有没有问题 | 用户现在想知道什么 |
| 要状态吗 | ❌ **绝对不能有** | ✅ 必须有 |
| 为什么 | 判定依赖历史 → 同一份报告在不同顺序下结论不同 → **召回率不再是确定的数字** | 没有历史 → 无法回答"那我该怎么办"、指代消解失败 |

**方向是单向的：审计结论 → 对话（只读）。**

如果对话能改结论，那"这份报告被判有问题"就取决于用户跟你聊了什么——
**审计器的可复现性没了**，简历上的 87.9% 也就不成立。

## 二、命令

```bat
:: 交互式对话（**会调模型、会花钱**）
.\.venv\Scripts\python.exe -m agent chat --session-id demo

:: 看策略现在怎么配（不花钱）—— 改完 chat_policy.py 用这个自检
.\.venv\Scripts\python.exe -m agent chat-budget

:: 看某个会话占了多少上下文、压缩过几次（不花钱）
.\.venv\Scripts\python.exe -m agent chat-inspect demo --show-context

:: 删除会话（隐私）
.\.venv\Scripts\python.exe -m agent chat-forget demo
.\.venv\Scripts\python.exe -m agent chat-forget --all
```

对话里可以用的命令：`/context` 看占用 · `/compact` 手动压缩 · `/exit` 退出。

**想带一份真实的审计结论进去**（这样对话只能解释它、不能改）：

```bat
.\.venv\Scripts\python.exe -m agent chat --audit-json my-audit.json
```

JSON 格式：`{"report_id": "...", "summary": "...", "findings": [...], "escalated": true}`

## 三、四条硬约束（我做的机制，有测试守着）

### ① 审计结论**一经冻结，不可改写**

`ChatSession.freeze_audit()` **只能调用一次**，第二次直接报错。
`frozen_audit` 是只读属性，**没有任何修改路径**。

### ② 压缩**只动对话历史**，受保护字段**结构上取不到**

`always_keep` 里列的字段（`profile` / `frozen_audit` / `pinned`）**根本不参与压缩**。

**不是"摘要时小心一点"，是结构上拿不到。**

> 为什么这点必须硬：靠摘要保住"我对海鲜过敏"是**不可验证的承诺**；
> 字段保护是**可测的**。丢了会出很隐蔽的错——第三轮说过敏，第七轮建议吃海产品，
> **没有任何报错，看起来还很合理**。

### ③ 截断**必须留痕**

摘要超长时截断，会写出"**…（更早的摘要已被截断）**"。
悄悄截断 = 让用户以为系统记得全部，**这比丢东西更危险**。

### ④ 会话隔离 + 可单独删除

每个会话独立存储、独立删除。`session_retention_days=0` 表示**不自动清理**——
**不许悄悄删用户数据**。

## 四、★ 你要改的地方（"在哪里改、怎么改"）

**全部改动都在 `agent/chat_policy.py`**（★你的文件★）。

| 你想改什么 | 改哪个字段 | 怎么改 | 改完怎么验证 |
|---|---|---|---|
| **压缩太频繁**（聊几句就压） | `max_turns_before_compact` | 调**大**（比如 12 → 20） | `agent chat-budget` 看新阈值 |
| **压缩后忘了刚说的** | `keep_recent_turns` | 调**大**（比如 6 → 10） | `agent chat-inspect <id> --show-context` 看最近的对话还在不在 |
| **压缩质量不好**（规则只会截断拼接） | `compact_mode` | 改成 `"model"` | 看 `chat-inspect` 的 `模型调用` 次数上升；**注意从此压缩不可复现** |
| **省钱**（不想为上下文多花钱） | `compact_mode` / `context_char_budget` | `"rule"` + 调小预算 | 看 `chat-inspect` 的字数 |
| **想永久保护某个新东西** | `always_keep` | 加**已有字段名**（`profile`/`frozen_audit`/`pinned`） | `pytest -q tests/test_chat.py` |
| **用户要求记住的事**（过敏史、长期用药） | 运行时填 `session.pinned` | 代码里 `session.pinned.append("我对海鲜过敏")` | `chat-inspect` 里会显示 |
| **改对话红线**（不许诊断/用药/实际方案） | `CHAT_PROMPT` | 直接改文字 | 手动试一句越界提问 |
| **定留存期限** | `session_retention_days` | 填天数（**现在 0 = 一直留着**） | — |
| **摘要太长/太短** | `compact_summary_chars` | 调 | 触发一次压缩看 `摘要 N 字` |

### ⚠️ 一处需要我配合的（这条边界要说清）

加 **`always_keep` 里已有的字段名**（`profile` / `frozen_audit` / `pinned`）——你自己改就行。

但如果你想保护一个**全新的字段**（比如"既往病史"单独存），
需要在 **`agent/chat.py` 的 `ChatSession.protected()`** 里加一行取值——
**那是我的文件，告我一声我加**，或者你自己加也可以，位置在：

```python
# agent/chat.py 的 protected() 里
available = {
    "profile": self.profile,
    "frozen_audit": ...,
    "pinned": list(self.pinned),
    # ← 新字段加在这里（左边是 always_keep 里写的名字）
}
```

**为什么不能全自动**：新字段得先存在某个地方，代码得知道去哪取。
**这不是判断，是接线**——所以这行归我。

## 五、压缩的取舍（你要定的那个）

### 规则压缩 vs 模型压缩

| | 规则（`rule`，当前默认） | 模型（`model`） |
|---|---|---|
| 可复现 | ✅ 完全确定 | ❌ 每次摘要可能不同 |
| 成本 | 免费 | 每压一次一次调用 |
| 质量 | 粗糙（截断 + 拼接） | 好（真能概括） |
| 可测 | ✅ 能写断言 | 难 |

**规则压缩刻意不做真正的概括**——因为规则做不了概括，
**假装能做才是问题**。它的质量上限就是"能想起聊过什么"。

**这一层的不可复现不会污染审计数字**，因为审计结论是冻结的，
压缩只影响"对话怎么表达"。**但如果你要求对话历史本身可复现，就必须留在 `rule`。**

## 六、还没做的（不假装做了）

| | 状态 |
|---|---|
| **人工复核反馈回路** | ❌ 未做。**这才是真正能提升效果的"上下文"**——把人工判断回流成新样本 |
| 跨会话用户档案（历史体检、个人基线） | ❌ 未做。涉及医疗隐私，要单独设计加密与留存 |
| 上下文用 token 而非字符计量 | ❌ 现在按**字符**算。字符是 token 的粗略代理，够用但不精确 |
| 会话导出/迁移 | ❌ 未做 |

> **优先级建议**：如果目标是"让系统更好"，**人工复核反馈回路比多轮对话值钱得多**——
> 前者能提召回率，后者只提升体验。
