## 2. T2 · 护栏规则

### 要解决什么问题

护栏是模型前面的第一道闸，把**明显的那批**便宜地挡掉，让模型只处理真正难的。
（**护栏命中就不调模型**，省钱。）

### 怎么做

打开 `agent/guardrails.py`，拉到文件末尾的 **`EXTRA_PATTERNS`**：

```python
EXTRA_PATTERNS: tuple[GuardrailRule, ...] = (
    GuardrailRule(
        name="G-<你起的名>",
        category="conclusion",        # diagnosis | treatment | dosage | conclusion | other
        patterns=("词一", "词二"),     # ⚠️ 新词直接写，不要从 SAFETY_TERMS 里筛
        note="它防的是什么错",
    ),
)
```

要"中间隔几个字也算"就用正则：

```python
    GuardrailRule(
        name="G-CERTAINTY-PATTERN",
        category="conclusion",
        patterns=(r"已经属于.{0,6}(范围|阶段)",),
        note="把不确定的结果说成确定结论。",
        is_regex=True,
    ),
```

### ⚠️ 两个必须知道的坑

**坑一：不要用"从 `SAFETY_TERMS` 里筛"的写法加新词。**
新词当然不在已有词表里，筛出来是空元组——规则看着加上了，**实际永远匹配不到**。
（现在空 `patterns` 会**直接报错**，这是故意的。）

**坑二：新类别名要登记进 `agent/policy.py`**（见 T1 细节 2、T8）。

### 怎么验证（这一步别跳）

**① 列规则 + 自检每条规则有没有失效**（不调模型、不花钱）：

```bat
.\.venv\Scripts\python.exe -m agent guardrails
```

它会把每条规则列出来，并**把它自己的词喂回去看命不命中**——
死规则会被明确标出（死规则不报错，只是永远不起作用）：

```
★你的  G-CONCLUSION-KEYWORD
        类别：conclusion    模式：4 个
        词表：['基本可以确定', '已经属于', '可以认定为', '不用就医']
        自检：✅ 全部 4 个词都能命中
```

**② 用一句真实的话验证**（同样不花钱）：

```bat
.\.venv\Scripts\python.exe -m agent guardrails --text "目前已经属于糖尿病范围了"
```

```
护栏命中（命中即判越界，不必问模型）：
  · 规则 G-CONCLUSION-KEYWORD（类别 conclusion） 命中词/正则：'已经属于'
```

只看某一条规则：加 `--rule G-CONCLUSION-KEYWORD`。

**③ 跑完整链路（护栏 + 模型）**：

```bat

```

`check` 和 `guardrails` 的区别：`guardrails` **只看护栏**（免费）；
`check` 会走完整判断——**护栏命中就不调模型，没命中才调模型**（那就花钱了）。

**看不到"命中词"就是没生效**，不要靠感觉。

## 3. T3 · 真实问句集 ★最能体现产品感觉

### 要解决什么问题

现在 31 条检索问句是**模板生成的**（"ALT 偏高怎么办"），太干净。
实测：模板集 Recall@1 **93.5%**，真实问句集只有 **80.0%**。

**真实问法上的 Recall@1 才是能写进简历的数字。**

### 先搞懂一件事：你标的是"答案在哪一条"，不是"医学上正确答案是什么"

**这是最容易误会的地方。**

系统要考的是**检索**：给一句问话，能不能从知识库里**翻出正确的那一条**。
所以每行 JSON 里的 `metric` / `guideline` **不是医学结论**，
而是**"这句话应该被翻出来的那条知识库条目"**。

```json
{"query": "转氨酶高是不是熬夜熬的", "metric": "alt"}
```

这行的意思是：

> "当用户这么问时，**检索应该返回 `kb://metric/alt` 那条（转氨酶那张卡）**。"

**你不需要判断"熬夜到底会不会让转氨酶高"**——那是医学问题。
你只需要判断：**这句话该去查哪一条。**

**为什么必须你标**：程序不知道"该查哪条"，它只能照着标准答案算分。
标准答案如果是我编的，那这个分数就是在考"我编的题"，没有意义。

### 可用的值（照抄这两张表）

**指标类（8 个）**——用 `metric`：

| 填什么 | 是哪个指标 |
|---|---|
| `alt` | 丙氨酸氨基转移酶（ALT, U/L）——俗称"转氨酶" |
| `ast` | 天门冬氨酸氨基转移酶（AST, U/L）——俗称"谷草" |
| `ggt` | γ-谷氨酰转移酶（GGT, U/L） |
| `crea` | 肌酐（CREA, umol/L） |
| `ua` | 尿酸（UA, umol/L） |
| `tc` | 总胆固醇（TC, mmol/L） |
| `fpg` | 空腹血糖（FPG, mmol/L） |
| `hgb` | 血红蛋白（HGB, g/L） |

**指南类（7 个）**——用 `guideline`：

| 填什么 | 是哪个条目 |
|---|---|
| `critical-value` | 什么是危急值，看到危急值应该怎么办 |
| `recheck` | 复查的意义与时间安排 |
| `fasting` | 抽血前的准备（空腹、能不能喝水） |
| `urate-diet` | 尿酸与日常饮食的一般关系（海鲜、酒、内脏） |
| `lipid-lifestyle` | 血脂与生活方式的一般关系（血脂、饮食、运动） |
| `anemia` | 血红蛋白偏低的一般说明（贫血） |
| `disclaimer` | 本工具能做什么、不能做什么（免责声明） |

### 怎么做

**第一步：照着 5 条示例改写。** 先改一条也行：

```json
{"query": "谷丙转氨酶高是什么原因", "metric": "alt", "note": "用别名'谷丙'，不用'转氨酶'"}
```

**第二步：每加几条就跑一次**，看 N 有没有变大：

```bat
.\.venv\Scripts\python.exe -m rag eval
```

看到"真实问句集（**N** 条）"里的 N 变了就说明加对了。
格式写错会**报错并带行号**（`第 7 行缺少 metric 或 guideline`），不会静默跳过。

### 什么算"难问法"（≥10 条）

难点不在指标对不对，而在**用户会不会不按文档的用词说**：

| 难在哪 | 例子 | 假设答案 |
|---|---|---|
| **用别名**，不写标准名 | 谷丙高怎么办 / 血色素低要紧吗 | `alt` / `hgb` |
| **口语、省略** | 转氨酶有点高要紧不 | `alt` |
| **带因果猜测** | 肌酐高是不是喝水少 | `crea` |
| **跨指标**（问的是另一件事） | 尿酸高能不能吃海鲜 → 答案在**饮食**条目 | `urate-diet` |
| **一次问两件事** | 血糖高要不要复查 | `recheck` 或 `fpg`（**二选一，你定哪个更该被返回**） |
| **错别字** | 胆固淳高怎么办 | `tc` |
| **问指标、答案是通用指南** | 血脂高是不是要吃素 / 多久复查 | `lipid-lifestyle` / `recheck` |

⚠️ **"一次问两件事"那类两边都说得通——你要选一个，并想清楚为什么。**
这正是"产品判断"，面试官爱问。

### 验收标准

- 至少 **40 条**（目标 100），其中 **≥10 条**是上面的难问法
- `python -m rag eval`，真实集与模板集分数**分开记录**
- **能回答**：你写的哪几条让分数掉下来了？为什么？
