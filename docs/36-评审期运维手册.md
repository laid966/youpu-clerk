# 36 · 评审期运维手册（12/10-14 初赛窗口）

> 目标只有一句：**评委任何时刻点开链接，60 秒内能玩通演示。**
> 本手册假设最坏情况逐条给动作，不假设"应该没事"。

- [ ] 支付路径人工走一遍：下单 → 真钱 ¥6.9 → 权益生效（G3 已验证过的流程再确认一次）
- [ ] 全局预算确认：`sqlite3 data/clerk.db "select * from usage_daily where token='__global__'"` 离 500 还远
- [ ] 手机 4G 网络（非 WiFi）打开站点一遍——评委可能用手机

## 1. 评审期每日早检（5 分钟）

```bash
python -m clerk.smoke https://你的域名        # 六项门禁
systemctl status clerk --no-pager | head -5  # 进程与 uptime
tail -20 /var/log/clerk.err.log              # 昨夜有无异常（journalctl 亦可）
```

## 2. 事故处置树

| 症状 | 第一动作 | 然后 |
|---|---|---|
| 站点打不开（连接拒绝） | `systemctl restart clerk` | 再 smoke；仍失败看 `journalctl -u clerk -n 50` |
| 站点 502/504 | `systemctl status caddy` + `systemctl status clerk` | Caddy 挂→restart caddy；clerk 挂→restart clerk |
| 页面能开但 API 全 500 | `journalctl -u clerk -n 50` 看栈 | 常见：磁盘满（`df -h`）、sqlite 锁（重启即解） |
| **LLM 话术变机械** | 不用动 | DeepSeek 欠费/宕机 → TemplateJudge 自动接管，产品功能完整，仅文案降级；充钱即恢复 |
| 全站 503（GLOBAL_QUOTA_EXHAUSTED） | 改 `clerk/config.py` 的 `GLOBAL_DAILY_LLM_BUDGET` 调高 → restart | 说明今天真实用量超预期（好事）；或遭脚本攻击（看 usage_daily 里 token 分布，全是新 token 即攻击，考虑临时调低并观察） |
| 支付回调没到（用户付了钱权益没生效） | **先别慌**：让用户刷新/重开付费页 → 前端轮询 `/api/pay/query` 会主动查询兜底 | 仍不行：后台用订单号手查 `alipay.trade.query`（或让用户提供支付宝账单截图，人工 `notify-dev` 补单——仅 dev 环境；生产补单走 query 路径） |
| 演示模式某步报错 | 截图留证，`demo-restart` 重播 | 演示是 TemplateJudge 确定性路径，报错=真 bug：记下来赛后修，评审期用 mock 模式兜底（`?mock=1` 永远可用） |
| 数据库损坏（极小概率） | 停服务 → 用昨夜备份 `cp backups/clerk-YYYY-MM-DD.db data/clerk.db` → 起服务 | 丢失的只是当天台账；演示与商品档案可秒级重建（seed_demo/重建商品） |

## 3. 评委体验保险丝（三道，全部已内建）

1. **无 key 可玩**：演示模式强制 TemplateJudge，DeepSeek 全挂也不影响评委
2. **无后端可玩**：`?mock=1` 全站离线回放真实后端抓取的剧本（极端情况：服务器只剩静态文件也能演示）
3. **无扩展可玩**：粘贴模式 = 手机复制消息进工作台，评委不装任何东西也能体验核心闭环

## 4. 账号与密钥清单（★只有你有★，赛前抄到纸上离线保存）

| 项 | 在哪 |
|---|---|
| 服务器 SSH | 云控制台 + 本地密钥 |

## 5. 沟通预案

- 评委/组委会联系渠道保持畅通（报名时填的手机+邮箱，每天看两次）
- 若被问"支付是不是真的"：出示支付宝商家后台流水截图 + 台账导出（`/api/ledger` 即证据）
- 若被问"AI 会不会乱报价"：现场演示低价甩卖→转人工、还价破底价→引擎自拦（老王剧本第 1、5 步就是这两个场景）
