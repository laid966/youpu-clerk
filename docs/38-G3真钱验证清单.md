# 38 · G3 真钱验证清单（凭证到手当天，按序跑）

> 目标：用真钱走通"下单→收银台→异步通知→权益生效→台账留痕"，并**留下提交材料要的取证**。
> 预计耗时：沙箱 30 分钟 + 生产 15 分钟。任何一步不符，停下来把现象发我，不要跳过。

## 阶段 0 · 沙箱（不碰真钱）

1. [沙箱控制台](https://open.alipay.com/develop/sandbox/app) 领取：沙箱 app_id、应用私钥、**支付宝公钥**、沙箱买家账号
2. 服务器 `.env` 填沙箱四件套，并加一行：
   `ALIPAY_GATEWAY=<沙箱网关地址>`（控制台可见；代码默认生产网关）
3. `systemctl restart clerk`；定价页点「立即开通」→ 新标签应打开**沙箱收银台**
4. 用沙箱买家账号完成支付 → 回到工作台页：轮询应自动 toast「支付成功，权益已生效」
5. 核对四件事：
   - `GET /api/entitlements/me` → `plan=paid30, active=true`
   - `GET /api/orders` → 该笔 `status=paid`
   - 额度墙消失：免费额度设 0 也能出建议（或直接看配额不再 402）
   - **重放保护**：把同一条 notify 报文再 curl 一次 → 权益到期时间不变
6. 沙箱里做一次**退款演练**：商家后台退该笔 → 等/查通知 → 权益降回 free
   （退款演练只在沙箱做——生产那笔要留着当真实付费用户）

## 阶段 1 · 生产真钱小额

7. `.env` 换生产四件套 + `ALIPAY_NOTIFY_URL=https://你的域名/api/pay/notify` + `ALIPAY_RETURN_URL`；删掉沙箱网关行；restart
8. **用你自己的支付宝**真钱买一单早鸟（¥6.9）→ 三件套取证：
   - 支付宝账单截图（用户侧）
   - 商家后台该笔流水截图（商户侧）
   - 我们侧：`GET /api/orders` 截图 + 当天台账（`/api/ledger`）截图
   三侧对得上 = 商业闭环证据链完整（提交材料 §4 要用）
9. `python -m clerk.smoke https://你的域名` 6/6 → 进入 24h 观察期（docs/36 每日早检）

## 常见失败速查

| 症状 | 第一怀疑 | 动作 |
|---|---|---|
| 收银台打不开/报参数错 | subject 含特殊字符或金额格式 | 看我们日志里发出的 biz_content；subject 已自动清洗，金额必须两位小数 |
| 支付成功但权益没生效 | 通知没到（域名/备案/防火墙） | 看 caddy 访问日志有无 `/api/pay/notify` POST；没有→查 DNS/备案；有但 4xx→看 clerk 日志 |
| 通知到了但验签失败 | **把"应用公钥"当成了"支付宝公钥"**（最高频错误） | 开放平台→应用详情→密钥管理里复制"支付宝公钥"那一栏 |
| 前端一直轮询不确认 | return_url 回跳后轮询窗口 2 分钟已过 | 手动刷新工作台；或 `POST /api/pay/query` 一次（主动查询兜底通道） |
| ACQ.TRADE_HAS_SUCCESS | out_trade_no 重复 | 我们生成带随机后缀不应重复；若出现，把两笔订单号发我查时钟/随机源 |
