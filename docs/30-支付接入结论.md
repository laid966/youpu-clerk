# 30 · 支付接入结论（G2 调研备忘）

> 更新时间：2026-11-16。**关键变化：官方文档 11-15 更新，此前失效的"AI网页应用收款"
> 接入文档已恢复**，本备忘全部基于当天抓取的原文，链接见文末。

## 一、结论先行

**主路线已定：Vibe Pay · 基础收款能力 · AI网页应用收款。**

- 文档第一句："适用于在商家网页应用中使用支付宝支付功能，**支持个人收款场景**"
  ——G2 最大的悬念（个人身份能不能收款）官方文档给了肯定答案。
- 技术形态 = 支付宝标准**统一收单**：`alipay.trade.page.pay`（电脑网站支付，
  product_code 唯一枚举 `FAST_INSTANT_TRADE_PAY`）+ 异步通知验签 + 交易查询兜底 + 退款。
- 网关 `https://openapi.alipay.com/gateway.do`，RSA2 / UTF-8 / JSON / version 1.0。

**代码已全部落地**（`clerk/pay_vibe.py`，32 个离线密码学测试）：
凭证通过环境变量注入后**自动切换**到真实通道，代码零改动（`pay.get_adapter()` 动态选择）。

## 三、实现与文档的对应关系（评审答辩用）

| 官方文档纪律 | 我们的落点 |
|---|---|
| product_code 仅 FAST_INSTANT_TRADE_PAY | `pay_vibe.PRODUCT_CODE` 常量 + 测试断言 |
| subject 不可含 `/ = &` | `_sanitize_subject()` 清洗 + 测试 |
| 支付结果以异步通知/查询为准，不信同步跳转 | 权益只经 `/api/pay/notify` 与 `/api/pay/query` 变更；return_url 仅前端展示 |
| 通知必须验签（除 sign/sign_type 外字典序 k=v 拼接，RSA2） | `verify_notify()`；测试用自造密钥对伪造/篡改通知验证拦截 |
| 验签后二次校验 app_id / out_trade_no / total_amount / seller_id | app_id/seller_id 在 `verify_notify`；订单存在性与金额逐分核对在 `pay.handle_paid_notification`（钱的判断只有一处） |
| 只认 TRADE_SUCCESS / TRADE_FINISHED | server notify 分支 + 测试（WAIT_BUYER_PAY 只 ack 不入账） |
| 应答纯文本 success/failure；失败按 4m/10m/…/15h 重发 | PlainTextResponse + 状态机幂等（重放测试 10 次权益只发一次） |
| 未收到通知时主动查询兜底 | `/api/pay/query`（前端支付回跳后轮询 2 分钟） |
| 退款 12 个月内、原路返回、多次退款用不同 out_request_no | `refund_trade()` 已备好；TRADE_CLOSED+退款特征的通知自动触发权益降级 |

## 四、你要办的事（按序，预计半天 + 等审核）

1. **注册/登录支付宝开放平台**（open.alipay.com），创建**自研应用·网页/移动应用**，
   身份选个人（文档支持个人收款；若页面强制企业，走路线 B/C 并告诉我）
2. **配置 RSA2 密钥**：用支付宝官方"密钥工具"生成应用私钥/公钥，
   应用公钥上传平台 → 平台给你**支付宝公钥**
3. **签约"电脑网站支付"产品**（即 FAST_INSTANT_TRADE_PAY 对应产品）。
   官方推荐捷径：空目录跑 `npx -y @alipay/alipay-aipay@latest install`，
   让 Skill 引导完成签约入驻（它会按你的应用形态匹配路径）
4. **给我四个值**（发在会话里即可，我写进服务器环境变量；**私钥不要发到任何网页表单**）：
   `ALIPAY_APP_ID` / `ALIPAY_PRIVATE_KEY` / `ALIPAY_PUBLIC_KEY` / `ALIPAY_SELLER_ID`(2088 号)
5. **公网域名**（部署手册 §1）：notify_url 必须是公网 HTTPS 且不能重定向
   → 依赖服务器+备案，这是排期上真正的关键路径
6. 沙箱先行（可选）：[沙箱控制台](https://open.alipay.com/develop/sandbox/app) 拿沙箱
   app_id/密钥，把 `ALIPAY_GATEWAY` 换成沙箱网关即可全链路联调，代码不变

## 五、安全纪律（已内建，勿破坏）

- 私钥只存在于环境变量/服务器 `.env`（.gitignore 已挡）；**永不进仓库、永不进前端**
- `ALIPAY_SELLER_ID` 建议必配：开启通知 seller_id 强校验
- dev 模拟回调 `/api/pay/notify-dev` 仅 `CLERK_PAY_DEV=1` 开放，生产默认 403
- 未配置凭证时收银台诚实显示"通道接入中"，不假装能收款

## 六、仍未验证的事项（诚实清单）

1. 个人身份签约"电脑网站支付"的**实际审核条件与费率**——文档没写，要以签约页为准（待你操作时截图）
2. notify_url 域名是否强制 ICP 备案——大概率跟随服务器接入商要求（部署手册已按"要备案"规划）
3. 赛事规则对收款产品的指定范围（"接入至少一款 AI付 产品"——我们接 Vibe Pay 满足，但以你截图的规则原文为准）
